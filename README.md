# HEMS demand forecasting — dataset 266083

ITS8080 Energy Data Science project. One household with rooftop PV: hourly electricity demand, PV output, price and
weather from 1 July 2013 to 7 July 2014. The project goes from data cleaning to a **day-ahead forecast of hourly
demand** that a home energy management system (battery + PV) could plan with.

**Notebook:** [`notebooks/266083_project.ipynb`](notebooks/266083_project.ipynb)
[![Open in nbviewer](https://raw.githubusercontent.com/jupyter/design/master/logos/Badges/nbviewer_badge.svg)](https://nbviewer.org/github/eveplakk-crypto/its8080-hems-266083/blob/main/notebooks/266083_project.ipynb)
**View it in the notebook viewer (nbviewer):** https://nbviewer.org/github/eveplakk-crypto/its8080-hems-266083/blob/main/notebooks/266083_project.ipynb

## What the notebook covers

| Part | Content |
|---|---|
| 1 | Data loading, quality checks, decomposition and profiles of demand, PV and price |
| 2 | Missing values in `pv_mod1`: deletion, univariate and multivariate imputation, live (causal) alternatives |
| 3 | Demand and weather: statistics, driver ranking, distributions and transformations |
| 4 | Lag, calendar and weather features; availability at prediction time; feature ranking |
| 5 | Evaluation protocol (time-ordered split, walk-forward), MAE and nRMSE, baselines |
| 6 | Stationarity (ADF + KPSS), ACF/PACF, ARMA-family models, SARIMAX with hour of day |
| 7 | Out-of-sample rolling 7-day forecast (recursive and multi-output), error by horizon, 80 % prediction intervals |

Main results: the multi-output ridge model is the best model (validation MAE 0.221 kWh, nRMSE 0.644; forecast week
nRMSE 0.541). It loses to "same hour yesterday" on 4–6 July 2014, when the household appears to have been away.

## Run it

Tested with **Python 3.14.0**.

```bash
git clone https://github.com/eveplakk-crypto/its8080-hems-266083.git
cd its8080-hems-266083
python3.14 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# run the notebook top to bottom (about 8 minutes)
jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=1800 notebooks/266083_project.ipynb

# or open it interactively
jupyter lab notebooks/266083_project.ipynb
```

The same steps also run without Jupyter:

```bash
python main.py       # every step, 1–30
python forecast.py   # only the out-of-sample 7-day forecast (about 2 minutes)
```

## Reproducibility

- **Pinned versions** in `requirements.txt`.
- **Fixed random seed:** `SEED = 0` in `src/config.py`; `set_seeds()` fixes the Python, NumPy and hash seeds, and every
  scikit-learn estimator and random sample gets `random_state=0`.
- **Only raw data is committed** (`data/raw/`). Everything in `data/processed/` and `outputs/` is regenerated by the
  notebook; the figures are also embedded in the notebook.
- Checked by running the notebook from a fresh copy in a new virtual environment: no errors, and every result table
  matched the original run (differences at most 1e-16, from floating-point summation order).
